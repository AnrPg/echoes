Phase 0's reports arrived on 2026-10-10 (findings in [phase-0.md](phase-0.md#findings)). All five questions are answered
well enough to start every v1 module; one version case (later turns under an old version) is
unobserved and gets flagged.

## API conversation adapter (done)

`packages/adapter-chatgpt-api` (README there): parses the paged `conversations/:id` + `…/messages?before` responses and
`…/versions` into the tree. zod-validated; golden test over an anonymized fixture built from the second capture
(`scripts/anonymize-capture.ts`, with a leak check). `pageFollowUps()` tells the host which older page and which
versions to fetch next.

Findings that changed the plan while building it:
- **Turns are not grouped by `turn_exchange_id`.** In the capture, the regenerated answer has a different
  `turn_exchange_id` from its question. The active path is linear, so each message's parent is simply the message
  before it; a turn starts at each user message.
- **Synthetic root** `echoes:root` (hidden system node): the API never returns ChatGPT's root, and an edited first
  question needs a parent to be a sibling under.
- **`Node.notFetched`** (new optional model field, additive): `later-messages` on the leaf of a version on an earlier
  turn, `earlier-messages` on the root when the oldest page still has older pages.

Still assumptions, each pinned by a test so a real capture that differs fails loudly:
- `before` takes the page's `start_cursor` (names were captured, values were not). Same for `num_turns`'s value.
- Edited questions: the old question comes back with its own id (inferred from the count and shape of the fifth
  capture; ids were not compared).
- Stored `multimodal_text` messages look like the send request (`image_asset_pointer` parts).

## Markdown renderer (done)

`renderMarkdown(conversation, options)` and `convertMarkdownText(text, flavor)` in `@echoes/core` (README there).
Flavors: GitHub, Obsidian, CommonMark. Golden tests over a synthetic showcase chat in all three flavors, plus the
adapter fixture rendered end to end (`packages/adapter-chatgpt-api/tests/golden/*.md`).

Decisions:
- `\( \)`, `\[ \]` and `$$ $$` are math. The Phase 0 capture has `\(` in 9 messages, `\[` in 13, and no
  `$`-delimited math from ChatGPT. Single-`$` math is kept only by Pandoc's rule, because questions people type
  (and other providers) do use `$x$`; prices like `$5 and $10` never match it and are escaped.
- Link destinations are copied as is, so URLs holding `$` or `\(` are not rewritten.
- Built by two threads in parallel and merged (2026-10-11): the document renderer, `renderJson`, markdown-it block
  detection and GitHub's ``$`x`$`` form from one; the Pandoc `$` rule, link-destination skipping and the
  synthetic-root/`notFetched` model rules from the other.
- Code is protected by markdown-it's block parser (fences, indented code, HTML blocks) plus a CommonMark code-span
  scanner for inline code; markdown-it gives no source positions for inline tokens, so it cannot do that part.
- `markdown-it-texmath` is not used: it renders to HTML, and the Markdown output needs source-level rewriting. It
  comes back with the HTML renderer.
- No export timestamp in the output: exports are deterministic, so the same chat gives the same bytes.
- A version note moves to the next rendered message when its own message is filtered out (a hidden context message
  can head a regenerated answer, as in the fixture).
- Multi-traversal output (one file per traversal, shared prefix with branch sections) is Feature 6 and builds on
  `renderMarkdown({ path })`; not in this step.

## Decisions from the foundations step

- `Node.createdAt` is optional (plan had it required): when a provider gives no time, Echoes leaves it out rather than
  inventing one. In the Build Plan since 2026-10-11.
- Bot-check detection: `cf-mitigated: challenge` header, or a 403 with an HTML body. Both pause; neither is retried
  automatically.
- A pause re-runs the request that hit it after `resume()`; it does not count as a retry.
- Package license is `UNLICENSED` until the v1-gate decision (MIT proposed).

## Search normalization (done)

`normalizeText`, `normalizeWithMap`, `findMatches` and `tokenize` in `@echoes/core`, tested on Greek (tonos, final
sigma), Turkish (`İ`, `ı`), Hebrew niqqud, Arabic harakat and tatweel, Chinese, Japanese and Korean.

Decisions:
- Chinese and Japanese are indexed as overlapping character pairs, not with `Intl.Segmenter`: a segmenter's word
  list depends on the host's ICU version, and the same chat must give the same search results in every host.
- Turkish dotless `ı` folds to `i` as well as `İ`, so people typing without a Turkish keyboard still match.
- Japanese voicing marks (`が`) are kept; every other combining mark is dropped.
- Normalization runs per character cluster, so every match maps back to an exact range of the original text.

## Export progress and export folder (done)

Started by a parallel thread (its unfinished patch, `notes/wip-store-output-ports.patch`), finished and tested here.
`Store` and `OutputSink` ports with memory implementations; safe file names; `manifest.json` (published JSON Schema
`export-manifest.v1`) for incremental re-runs; resumable export jobs checkpointed after every chat
(`examples/export-job.ts` wires them together).

Fixed while finishing it:
- A "Cancel" saved while a job ran was overwritten by the job's next checkpoint. Every save now reads the stored
  `cancelled` flag first, and the loop stops before the next chat.
- Tabs and newlines in a title became `-`; they now collapse to one space like other whitespace.

Pitfall: incremental export trusts `updatedAt`. A chat changed without a new `updatedAt` would be skipped; passing
`emptyManifest()` ("Re-export all") is the escape hatch.

Still to build for bulk export: the extension's IndexedDB `Store`, the File System Access folder sink and the
streaming-zip sink (they need the browser), and the fetch loop (needs one capture with query values recorded).
