## Versions in an export

Settings on the export page:

- **Versions**: only the one shown in ChatGPT (default), or all versions.
- **Other versions go**: in the same file (shared turns once, then `## Branch k of n: name` sections) or in one file
  each (`<title> (branch k).md`). JSON always holds the whole tree.

A chat that has versions also gets a `## Conversation tree` Mermaid diagram and `<title>.tree.json` (format
`echoes-tree` v1: nodes depth-first with a short preview, `k/n` version positions and the active path). Chats without
versions get neither.

Branch names come from the forks along the path, e.g. `Turn 2 edited (v2) to Turn 5 regenerated (v1)`.

## HTML and PDF

- **HTML** is a format on the export page, for single and bulk export. Each chat is one self-contained page: CSS
  inline, math as MathML (rendered natively by the browser, so no math fonts or scripts), code highlighted with
  Shiki, no scripts at all (a Content-Security-Policy in the page blocks them). Raw HTML inside a chat is shown as
  text. Images and files are linked from the `<title>_files/` folder, as in Markdown.
- **Look** (theme): Like ChatGPT, Article, Compact notes, Print-friendly. Each follows the reader's light or dark
  setting; printing is always light.
- **Save as PDF** (on a single chat) renders the chat as HTML with images embedded and opens the browser's print
  dialog, where you choose "Save as PDF". The text stays vector and selectable.
- Print rules: long code wraps and may split across pages; code blocks up to 15 lines, notes, images and display
  math stay whole; tables shrink; reasoning summaries print open.

Decisions and limits:

- Math is MathML, not KaTeX's HTML+fonts output: files stay small and need no bundled fonts. Chrome, Edge, Firefox
  and Safari render MathML.
- Fonts are the system's, with fallbacks for Greek, Cyrillic, Hebrew, Arabic, CJK and emoji. Bundling fonts (the
  Build Plan item) is deferred: it would add megabytes to every file.
- Bulk PDF is not offered: printing many chats without a dialog needs the `debugger` permission, which shows a
  warning bar. Bulk HTML prints the same way, one file at a time.
- The Mermaid tree diagram is only in Markdown (HTML would need Mermaid's script); `tree.json` is written for both.

## Turn picker

On a single chat, **Pick turns…** opens the picker:

- A row per turn with its question, the start of its answer and badges (code, math, table, picture, attachment,
  citation, versions). Checkboxes; shift-click selects a range; All, None, Invert; a live "N of M selected".
- **Search** (typo-tolerant, the core `TurnIndex`): matching rows are highlighted with a counter; "Select only these"
  or "Add".
- **Rules**: rows of dropdowns (text contains, has content, every N, from…to, first/last N, model, asked between,
  has other versions), each "Is" or "Is not", combined with "all of" or "any of". They become a core `Rule` and run
  through `selectTurns`; a bad regular expression is shown, not thrown. Select only, add or remove the matches.
- **Parts of each turn**: the turn-definition toggles, loadable from the built-in presets, and "Save as preset"
  stores your own (in this browser).
- **Preview**: click a turn to see it rendered by the HTML exporter itself, in an isolated frame (no scripts). ← →
  move, Space includes or excludes, Esc closes. When the question was edited or the answer regenerated, a version
  switcher changes which version the picker shows; the turn list follows that version.
- **Export N turns** (Format setting) or **Save N turns as PDF**. Turns keep their numbers, so gaps show. JSON always
  holds the whole chat.

Decisions: the picker lives on the extension's export page, not as an overlay inside chatgpt.com: an extension page
cannot clash with ChatGPT's CSS, and nothing is injected into the site. The preview is a sandboxed iframe rather
than a Shadow DOM, for the same isolation plus no scripts. Saved presets apply to the picker; bulk export still uses
the built-in presets.

## Resources by turn

Format **Resources only** writes, per chat, a folder with no conversation text:

- `turn-03/` per turn: uploads, generated images and tool output files; each code block as its own file with the
  language's extension (`code-2.py`, `tool-code-1.py`); tool output text; canvas documents as `.md`; `links.md`
  with the turn's links and citations (a link that is also cited appears once, as a source).
- `index.md` lists everything by turn and says what happened to each file: saved, expired, the code sandbox was
  reset, could not be downloaded, or not included (attachments off). Nothing missing goes unmentioned.
- `resources.json` is the same list for programs (`echoes-resources` v1). It is not called `manifest.json` because
  the export folder's `manifest.json` already tracks incremental exports.

It follows the Include preset and works in the turn picker too (only the picked turns). It uses the version shown
in ChatGPT. Core plans it (`planResources`); the host only downloads files.

## Lineage ("Branch in new chat")

A chat's source is found, best evidence first:

1. **Recorded**: the branch monitor saw the branch being made (confidence 1). The service worker also fetches the
   source chat right then, through the same tab, and keeps it as `parentSnapshot`, so the fork survives if the
   source is later edited or deleted. JSON exports include the snapshot.
2. **ChatGPT's metadata** (`api-metadata`): branched chats carry the source chat's id on their messages (Phase 0),
   but not the fork message. Echoes finds the fork by comparing with the source, which it must have exported before.
   If it has not, the report says "export that chat too to link the two"; nothing is guessed.
3. **Inferred**: otherwise, the chat is compared with every chat exported before and older than it, by the longest
   shared start of visible messages (role and content; hidden messages skipped; the fork may be on any version).
   At least a question and an answer must match. Confidence is `0.6 + 0.1 per shared message` (up to 0.95) when the
   shared messages also match by id or time, `0.3 + 0.1 per message` (up to 0.7) on content alone, halved when two
   chats match equally (the older is chosen). Front matter says `branch_evidence: "inferred"`.

To make this work across runs, Echoes keeps a small skeleton of each exported chat (`ChatSkeleton`: tree shape and a
fingerprint per message, no text) in the extension's database. Bulk exports run oldest chat first, so sources are
usually seen before their branches.

Unverified, pinned by tests: whether a branched chat's copied messages keep the source's ids. Phase 0 saw that they
keep their creation times; matching uses content, with ids or times only raising confidence.
